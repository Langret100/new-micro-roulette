# 마이크로비트 캡슐 룰렛 — 설치·실사용 가이드

이 프로그램은 **마이크로비트 V2.21을 배터리와 함께 캡슐에 넣고 흔들면**, PC/웨일북 또는 안드로이드폰 Chrome의 브라우저 화면에서 상품 룰렛이 기본 최대 4초(운영 설정에서 3~10초 변경 가능) 동안 가속하고, 멈추면 짧은 브레이크 효과와 함께 등급별 가중 추첨으로 상품이 정해지는 행사 체험용 정적 웹게임입니다. 앱 설치, 계정, 유료 서버 및 별도 BLE 수신기는 필요하지 않습니다(사용 기기의 블루투스 기능은 필요).

## 새 화면 사용법

- 상단바 없음. 관객에게는 룰렛만 아주 크게 표시됩니다.
- 왼쪽 아래 **마이크로비트 연결**: 실제 무선 기기에 접속/해제합니다.
- 오른쪽 아래 **⚙ 운영**: 상품 명단, 수량, 지급 내역, 소리/음량, 가상 흔들기, 실시간 센서 진단을 여는 관리 패널입니다. 다시 누르거나 패널 밖을 누르면 닫힙니다.
- 오른쪽 아래 **⛶**: 전체화면 전환.
- 상품별 `총 수량`과 `지급 완료` 수량을 관리합니다. 남은 수량 0개인 상품은 **다음 회차부터** 룰렛에서 자동 제외됩니다. 상품명 중복도 개별 재고로 관리합니다.
- 기본 설정은 일반 당첨 결과 발표 8초 후 자동으로 다음 참가자를 준비합니다. **'한 번 더'** 당첨 시에는 5초 후 같은 참가자가 보너스 룰렛을 한 번 더 돌립니다. 보너스 회차에서는 '한 번 더' 칸이 잠시 제외됩니다. 보너스권만 마지막으로 남으면 보너스 전환 없이 일반 당첨이 되므로 실제 상품도 충분히 준비해 주세요. 가상 흔들기는 실제 재고를 차감하지 않습니다.
- 효과음 파일 10개는 `sounds` 폴더에 동봉되며 외부 서버에 업로드되지 않습니다.
- `⚙ 운영 → ▶ 효과음 10종 점검`을 누르면 시작·흔들기·칸 클릭·부스트·두구두구·당첨·품절·제동·카운트다운 타격음을 순서대로 직접 들을 수 있습니다. `10/10` 준비 확인 및 누락 파일 경고가 표시됩니다. 행사 시작 전에 스피커에서 실제로 듣고 음량을 맞춰 주세요.
- 기본 음량은 65%, 음소거 시 기존 재생음도 즉시 멈춥니다. 짧은 효과음이 겹치면 자동 음량 압축으로 과도한 피크를 완화합니다.

## V2.21 마이크로비트 첫 설정 — 최초 1회

1. PC에서 https://makecode.microbit.org/ 접속 → `새 프로젝트` 생성.
2. `고급 → 확장`에서 **Bluetooth** 확장을 추가합니다. `Radio` 확장 제거 안내가 나오면 허용합니다. (`Radio`와 Bluetooth는 동시 사용하지 않습니다.)
3. 프로젝트 설정에서 **No Pairing Required: anyone can connect over Bluetooth** 옵션을 켭니다. UI 문구는 MakeCode 버전에 따라 다를 수 있습니다.
4. `JavaScript` 편집기에 ZIP의 `microbit/main.ts` 내용 **한 줄만** 붙여넣습니다: `bluetooth.startAccelerometerService()`. 블록 전환 오류가 발생하면 Bluetooth 확장이 실제로 추가되었는지 확인하고, 계속 JavaScript로 작업하세요.
5. `다운로드`로 `.hex` 생성 → USB로 연결한 마이크로비트의 `MICROBIT` 드라이브에 복사합니다. **USB를 꽂아 둔 상태로도 전원을 공급하여 작동하며**, 이 경우에도 웹 룰렛의 센서 데이터 연결에는 PC 블루투스를 사용합니다. USB 케이블 자체로 룰렛 웹과 데이터가 연결되지는 않습니다.
6. AAA 배터리 팩을 꽂고 마이크로비트와 배터리를 **캡슐 안에 움직이지 않도록 부드럽게 고정**합니다. 충격 완충재 사용 권장.
7. 캡슐 전원을 켠 상태에서, PC Bluetooth 켜기 → Chrome/Edge에서 배포된 룰렛 웹사이트 열기 → `📶 마이크로비트 연결` → 장치 목록에서 `BBC micro:bit ...` 선택.

**참고:** V2.21은 V2 계열입니다. 호환성이 불확실한 오래된 제3자 HEX보다 현재 MakeCode에서 직접 생성한 HEX를 권장합니다. 소스 `.ts`는 제공되지만 미리 컴파일된 `.hex` 파일은 동봉하지 않았습니다. 펌웨어 실제 기기 플래싱은 아직 직접 검증하지 못했습니다.

외부 공식 자료:
- Bluetooth 가속도 서비스: https://makecode.microbit.org/reference/bluetooth/start-accelerometer-service
- micro:bit Bluetooth 개요: https://tech.microbit.org/bluetooth/
- BLE 가속도 프로파일·데이터 형식: https://lancaster-university.github.io/microbit-docs/resources/bluetooth/bluetooth_profile.html
- Chrome/Edge 연결 도움말: https://support.microbit.org/support/solutions/articles/19000161841-troubleshooting-connection-issues-in-micro-bit-createai

## 현장 연결 성공 확인 — 중요

연결 버튼을 눌러 **무선 연결됨**이 표시되는 것만으로 완전 검증은 아닙니다.

1. 왼쪽 아래 `✓ 센서 NN회/초`가 표시되는지 확인합니다. 신호가 안 들어오면 **센서 신호 없음**과 경고가 표시됩니다.
2. `⚙ 운영 → 실제 기기 수신 점검`에 `X ...g / Y ...g / Z ...g`가 보이는지 확인합니다.
3. 캡슐을 가볍게 움직일 때 값이 변하고, 한 번 강하게 흔들어도 룰렛이 움직이며, 계속 흔들면 속도가 더 올라갑니다.
4. 1개로 설정한 연습용 상품을 실제로 당첨시킨 뒤 재고가 정확히 1개 차감되고 다음 회차부터 해당 상품이 제외되는지 확인합니다. 필요하면 **마지막 지급 취소**로 되돌립니다.

연결에 실패하면: 마이크로비트에 Bluetooth 가속도 서비스가 들어있는 `.hex` 설치 여부, 배터리, PC 블루투스 활성화, Chrome/Edge 브라우저, HTTPS 주소, Windows/기관 관리 정책을 확인하세요. 기기를 재부팅하고 다시 연결해 보세요.

**안전 처리:** 룰렛 회전 중 BLE 데이터가 끊기거나, 브라우저가 백그라운드로 전환되거나, 기기 연결이 끊기면 해당 회차는 지급 없이 취소됩니다. 흔들림으로 판정될 만큼 충분한 충격이 한 번 발생해도 참가 회차가 시작됩니다. 정지 직전 바늘 위치는 당첨 상품 선택에 영향을 미치지 않습니다.

## 사이트 올리기

ZIP의 최상위 `index.html`, `style.css`, `app.js`, `roulette-core.js`, `inventory-core.js`, `sounds/`를 그대로 **GitHub Pages 또는 Cloudflare Pages**에 올립니다. 폴더 경로를 유지하세요. 프로그램은 정적 파일만 사용하고 서버 측 기능은 필요하지 않습니다. HTTPS에서 운영하세요. `file://` 방식은 브라우저 보안 정책 때문에 BLE/사운드가 정상 동작하지 않을 수 있습니다.

상품 명단·재고·기록은 **현재 브라우저의 로컬 저장소**에 보관됩니다. 여러 PC 또는 서로 다른 브라우저 사이에 자동 동기화되지는 않습니다. 시크릿 모드/사이트 데이터 삭제/브라우저 저장 차단 시 기록이 유지되지 않을 수 있습니다.

## 기술 사양

- BLE: micro:bit Accelerometer Service `e95d0753-251d-470a-a062-fa1922dfa9a8`
- 데이터: `e95dca4b-251d-470a-a062-fa1922dfa9a8`, `X/Y/Z signed int16 little-endian`, 단위 milli-g
- 측정 주기: `e95dfb24-251d-470a-a062-fa1922dfa9a8`에 `20ms`(2바이트 LE)를 요청. 기기가 쓰기를 거부하면 기본 주기로 알림 수신 시도.
- 진행: 중력 저주파 필터로 방향 영향을 제거 → 흔들기 강도·횟수 추정 → 속도 가속. 최대 4초 흔들기(시작 1초 후 3·2·1 표시, 매 숫자마다 묵직한 퉁 효과음), 정지 감지 약 0.2초 후 급제동 0.26초(감지 포함 목표 약 0.5초) → 속도의 최고 기록을 바탕으로 등급 가중 추첨 → 실제 화면에 멈춘 칸과 당첨 상품 일치. 빨강 최고 구간(86% 이상)에서 다른 등급 재고가 있다면 최저 등급을 제외합니다.
- 렌더링: Canvas는 크기/목록 변경 시 그리며 회전은 CSS transform으로 처리. 물리 PC의 60fps 보장은 아직 측정되지 않았습니다.

## 추가 기기 화면 점검

PC 1366×768, FHD, 1024×768, 모바일 390×844·360×640 외에 320×568, 가로 844×390, 1280×600, 768×1024에서도 룰렛이 화면 안에 들어오는지 확인했습니다. 특히 가로 844×390에서 원판 아래가 잘리는 문제를 수정했습니다.

## 시험 결과와 제한

Node 단위 검사와 Chromium 브라우저에서 5개 화면 크기 UI 검사, **가상 GATT 장치가 공식 UUID와 데이터 형식을 사용해 보내는 가속도 알림**으로 연결→회전→정지→당첨→재고 차감·취소·신호 상실·회복을 확인했습니다. 화면은 헤드리스 Chromium 렌더링 후 캡처 검수했습니다.

**실제 마이크로비트 V2.21 하드웨어 연결·주변 무선 간섭·기기 센서 감도·현장 오디오·웨일북 실제 FPS는 테스트 환경에 물리 기기가 없어 검증하지 못했습니다.** 가상 GATT 성공을 물리적 연결 성공으로 표현하지 않습니다.

## 안드로이드 휴대폰에서 사용하기 (GitHub Pages)

1. ZIP을 풀고 `index.html`, `style.css`, `app.js`, `roulette-core.js`, `inventory-core.js`, `sounds/`, `보상명단.txt`를 **GitHub 저장소 최상위**에 업로드합니다. 파일과 폴더명을 바꾸지 마세요.
2. GitHub 저장소 `Settings → Pages → Build and deployment → Deploy from a branch → main / (root) → Save`를 선택합니다. 공개 저장소를 이용하면 일반 무료 계정에서 쉽게 배포할 수 있습니다.
3. 배포된 `https://<사용자명>.github.io/<저장소명>/` 주소에 **안드로이드 Chrome**으로 접속합니다. (배포 반영에는 시간이 걸릴 수 있습니다.)
4. 휴대폰 Bluetooth를 켜고 화면 아래 `📶 마이크로비트 연결` → `BBC micro:bit ...`을 선택합니다. 마이크로비트 V2.21에는 앞 절의 MakeCode HEX를 설치해야 합니다. **기기 선택은 사용자 터치가 필요하며 자동 연결은 브라우저 정책상 보장하지 않습니다.**
5. 아래 `⚙ 운영 → 상품·재고 관리`에서 상품명·총 수량·지급 완료를 편집하고 저장합니다. 재고가 0이면 다음 회차부터 자동 제외됩니다.
6. **아이폰 Safari는 Web Bluetooth를 지원하지 않습니다.** 일부 Android 내장 브라우저/앱 내 웹뷰도 안 될 수 있으므로 Chrome을 직접 열어 사용하세요.

### 기기를 변경할 때 상품 목록 옮기기

운영 → 상품·재고 관리 → `↓ 상품·재고 백업`으로 JSON 파일 저장 후, 다른 기기에서 같은 사이트에 접속하여 `↑ 상품·재고 불러오기`를 눌러 선택하세요. **현재 상품과 누적 지급 수량을 가져오지만, 기존 기기의 당첨 기록은 새 기기로 복사되지 않습니다.** 불러오는 기기의 이전 당첨 기록도 초기화됩니다. 다른 기기에서 동시에 운영하면 실시간 재고 동기화가 되지 않습니다. 한 번에 한 기기에서 진행하는 것을 권장합니다.

### 모바일 행사 점검

- 일반 Chrome 탭에서 실행하고, 휴대폰 화면 잠금/배터리 절약 모드로 인해 BLE가 중단되지 않도록 주의합니다. 백그라운드 전환 시 진행 중 회차는 안전하게 취소됩니다.
- 처음 한 번 화면을 터치해 효과음 재생을 활성화하고 `운영 → 효과음 8종 점검`으로 소리를 확인합니다.
- 모바일 실기기 Bluetooth 통신 성공 여부는 아직 실제 마이크로비트를 연결해 확인하지 못했습니다.

## 화면 구성 및 속도 게이지
화면은 검은색 배경, 중앙의 대형 룰렛, 오른쪽의 12칸 사다리꼴 SPEED 게이지로 구성됩니다. 하단의 '운영' 버튼에서 상품 이름과 수량을 변경할 수 있습니다.
속도 게이지는 흔들림 강도만의 임의 수치가 아니라 실제 룰렛 회전 속도(최대 40rad/s)를 기준으로 0~100%로 표시합니다. 아래쪽 녹색 칸부터 위쪽 붉은색 칸까지 하나씩 차오르고, 흔들기를 멈춰 룰렛이 느려지면 게이지도 차례로 내려갑니다. 가상 흔들기에서도 확인할 수 있습니다.

설정과 재고는 해당 브라우저에 저장되며 휴대폰과 PC 간 실시간 공유되지 않습니다. 운영 패널의 상품·재고 백업/불러오기로 기기 간 옮길 수 있습니다. GitHub Pages HTTPS에서 안드로이드 Chrome/PC Chrome·Edge의 Bluetooth 기능을 사용할 수 있습니다. 실제 기기 연결 검증은 현장에서 별도 수행해야 합니다.

## 등급별 당첨 및 기본 TXT (추가)

- GitHub Pages에 `보상명단.txt`를 올리면 신규 방문자에게 처음 한 번 기본 명단을 적용합니다. TXT의 각 줄은 `등급|상품명|총수량` 형식이며 1 일반, 2 고급, 3 희귀, 4 전설 등급입니다. `#`으로 시작하는 줄은 주석이며 전부 비워 놓으면 상품 없이 시작하여 기기에서 직접 입력합니다.
- 방문자가 자신의 휴대폰이나 PC에서 수정해 저장하면 그 **기기의 로컬 저장 데이터가 우선**이며 사이트에 올린 TXT가 덮어쓰지 않습니다. 각 기기 간 자동 재고 동기화는 없습니다.
- 보상이 높은 등급일수록 최고 흔들림 속도가 높을 때 뽑힐 확률이 커집니다. 빨간 구간 도달 시 최저 등급이 다른 등급이 재고가 있는 한 제외됩니다.
- 흔들기를 멈추면 약 0.2초 정지 감지 뒤 0.26초 급제동하며 `brake.wav` 효과와 즉시 당첨 팝업/효과음이 실행됩니다. 실물 센서의 패킷 전달과 모바일 브라우저 프레임 사정에 따라 체감 시간은 다를 수 있습니다.

## 빠른 흔들기 연출·바늘 조작 방지

- 유효한 한 번의 흔들림만 있어도 참여할 수 있습니다. 4초 이내 여러 번 강하게 흔들면 최대 속도와 높은 보상 등급의 가중치가 상승합니다. 고속에서는 원판 실회전 속도 약 40rad/s(6.4바퀴/초 상한), 바깥쪽 회전 빛줄기·속도 잔상·밝은 헤일로·가속음을 적용합니다.
- **상품을 고르는 난수 추첨은 바늘 위치와 무관하게 정지 신호를 받은 뒤 진행**됩니다. 브라우저 crypto.getRandomValues 사용 가능 시 이를 활용하며, 당첨된 칸에 맞춰 브레이크 종료 위치가 조정됩니다. 바늘이 특정 칸 앞에 있을 때 짧게 흔들어 노리는 행위는 유리해지지 않습니다.
- 흔들기를 멈추면 정상 BLE 데이터가 계속 들어오는 것을 전제로 약 0.2초 이후 0.26초 급제동(목표 합계 약 0.46초)과 함께 곧바로 결과 팝업을 띄웁니다. 모의 시험을 통과했으며 물리 기기에서 체감 지연은 별도 측정이 필요합니다.
- 위 확률은 사용자와 공유하는 행사 규칙입니다. 고속 참가자에게 높은 등급의 당첨 가능성이 높아지지만, 무조건 최고 등급이 당첨되는 방식은 아닙니다.

## 손가락/마우스로 직접 돌리기 (수동 조작)
- 별도의 수동 회전 버튼 없이 룰렛 원판을 누른 채 **원을 그리듯 드래그**합니다. PC 마우스와 안드로이드 터치를 지원합니다.
- 손을 떼면 약 **0.26초 동안 '끼익!' 급제동**한 다음 당첨 상품이 공개됩니다. 오래 누른 채 유지해도 한 회차의 최대 조작 시간은 **4초**입니다.
- 드래그 속도가 빠를수록 속도 게이지가 상승하고 높은 상품 등급의 확률이 올라갑니다. 최고 빨간 구간에서 다른 등급의 재고가 남아 있다면 최하 등급은 후보에서 제외됩니다.
- 바늘 근처에서 드래그를 멈춰도 상품을 지정할 수 없습니다. 상품은 등급별 가중 추첨으로 정하고, 룰렛을 해당 상품 위치까지 추가 회전시켜 멈춥니다.
- 단순 탭은 시작하지 않습니다. 브라우저가 터치를 취소하면 상품을 지급하지 않고 해당 회차를 취소합니다.
- 기본 Bluetooth 흔들기 체험과 상품 관리, GitHub Pages 운영 방식은 그대로 유지됩니다. BLE 연결 없이도 수동 조작 가능합니다.

### 수동 회전 관성 및 만화 브레이크
- 룰렛 원판을 드래그 후 놓으면, 최고 속도가 92% 미만일 때 약 2초 동안 관성으로 돌면서 서서히 멈춥니다.
- 최고 게이지 12/12칸 도달 시에는 기존 약 0.26초 급제동합니다. 마이크로비트 흔들기 연결 방식도 기존 급제동을 유지합니다.
- 정지 직전 '끼이익!!' 만화 효과, 빛줄기, 연기, 프레임 흔들림 및 브레이크 효과음이 나옵니다.
- 상품은 항상 등급별 확률로 결정되고, 손을 뗀 위치와는 무관합니다.


## 카운트다운 시간표 (개정)
- 체험 시작 후 0~1초: 숫자·카운트다운 타격음 없이 자유롭게 가속
- 1~2초: **3** 표시 + 묵직한 퉁! 1회
- 2~3초: **2** 표시 + 묵직한 퉁! 1회
- 3~4초: **1** 표시 + 묵직한 퉁! 1회
- 4초 도달: 자동으로 감속·브레이크·등급별 결과 발표
- 참가자가 일찍 멈추거나 드래그를 놓으면 남은 카운트다운은 생략하고 기존 정지 로직에 따라 결과 공개
- 당첨 후 *한 번 더* 보너스 회차의 **5초 자동 재진행**은 별도 기능으로 변경되지 않습니다.


## 운영 설정: 최대 흔들기 시간 (2026-11-18)
- 화면 오른쪽 아래 **⚙ 운영 → 운영 도구 → 최대 흔들기·드래그 시간**에서 3~10초 중 선택할 수 있습니다. **기본은 4초**입니다.
- 선택한 값은 `capsule-spin-duration`으로 **현재 기기/브라우저**에 저장되어 새로고침해도 유지됩니다. GitHub의 보상명단 TXT와는 별도로 보관됩니다.
- 카운트다운은 마지막 3초에만 `3 → 2 → 1`로 표시되고 숫자마다 묵직한 타격음이 한 번 납니다. 4초는 **첫 1초 무표시**, 5초는 **첫 2초 무표시**, 3초는 바로 숫자 3부터 시작합니다.
- 손을 떼거나 흔들기를 멈추면 남은 숫자는 생략합니다. 저속 수동 드래그는 기존 2초 관성 회전, 완충 속도와 Bluetooth는 기존 급제동 규칙을 유지합니다.
- 회전 중 설정 변경은 막고, 회차가 끝난 뒤 변경하도록 안내합니다. 다른 기기에는 설정이 자동 공유되지 않습니다.


## 전설 연출 및 긴 상품명 표시 (최신)

- `전설`(4등급) 당첨에만 시네마틱 효과를 적용합니다. 어두운 화면 → 금빛 문양·광선 → 전설 보상 공개 순서로 진행되며, 전용 사운드 `sounds/legendary.mp3`가 추가되어 총 효과음은 10종입니다. 다른 등급은 기존 당첨 연출을 유지합니다.
- **당첨된 상품 이름**은 띄어쓰기 기준으로 단어를 묶어 가운데 정렬합니다. 한 줄에 들어가면 한 줄, 길면 최대 두 줄로 줄바꿈합니다. 카드 폭보다 길 경우 글꼴 크기를 자동 축소합니다. 공백 없이 긴 단어는 예외적으로 글자 사이에서 나누며, 원래 전체 상품명은 접근성 이름에 보관합니다.
- 한 상품의 이름은 **최대 48글자**까지 등록할 수 있습니다. 룰렛 회전 중에는 칸 크기에 따라 상품명이 축약되어도, 당첨 결과에서는 가능한 한 전체 이름을 보여 줍니다.
- 844×390 등 높이가 짧은 가로형 모바일 화면에서도 일반·전설 결과 카드와 다음 참가자 버튼이 보이도록 보정했습니다. 기기를 회전하면 글꼴 크기와 줄바꿈을 다시 계산합니다.
- 운영 패널에서 **최대 흔들기·드래그 시간 3~10초**를 선택할 수 있고 기본은 4초입니다. 모든 설정에서 마지막 3초에 3·2·1과 타격음이 나옵니다. 기기별 브라우저에 저장됩니다.

**검증 범위:** Chromium PC·모바일 화면 크기와 모의 Web Bluetooth 센서로 검증했습니다. 실제 V2.21 기기 및 스마트폰과의 현장 연동, 스피커 청감, 60fps는 별도 실측이 필요합니다.
